# R19.6 Digital Frequency Stability Guard

Baseline: iScanMR10 R19.5.1 compile-fix (R19.5 single ALSA owner preserved)

## Root cause addressed

Live R19.5 telemetry proved that D-Star can reach a healthy steady state:

- TCP delivery ratio ~1.000
- IF delivery ~48 kSPS
- D-Star sync = 1
- MBE ~= 50 fps
- PCM8 ~= 8 kSPS
- PCM48 ~= 48 kSPS
- continuity = continuous
- codec_errors = 0

During the same call, Qt emitted many `dspcontrol.offset_freq` messages from
`SpectrumGLPlot.offset`. The receiver NCO moved by several kHz while D-Star was
synchronized, after which `sync_losses` increased and MBE/PCM cadence collapsed.

R19.6 treats a synchronized/active digital call as a frequency-stability
critical section.

## Changes

### 1. Digital voice lock follows AstraRX state

`SpectrumGLPlot.qml` now listens directly to
`Mainwindows::digitalVoiceStateChanged()` and normalizes DMR/YSF/D-Star/NXDN
mode names.

The hold is active only when:

- the current receiver mode is digital,
- the incoming `digital_voice.mode` matches the current mode, and
- `synchronized == true` or `voice_active == true`.

This prevents stale state from a different digital mode from locking tuning.

### 2. Auto-stop digital scan on synchronization/voice

When the hold becomes active:

- `scanTimer` is stopped,
- scan state becomes false,
- any unsent offset command is discarded,
- any in-progress digital drag preview is cancelled.

Digital scan dwell is at least `dwellMs` (default 500 ms), while analog keeps
its legacy 20 ms progression. This prevents the old 20 ms scan producer from
being coalesced into multi-kHz NCO jumps across a 6.25 kHz channel.

### 3. Digital drag is preview-only until release

For a digital receiver, dragging the carrier cursor changes only the local
cursor/readout. It does not emit `offset_freq` while the pointer moves.

On release, one request is committed through `requestReceiverFrequency()` if
the decoder is not locked. If synchronization arrives during the drag, the
preview is discarded and the confirmed/locked frequency is restored locally.

Analog drag behavior remains unchanged.

### 4. Digital offset command debounce

- Analog: 20 ms (unchanged)
- Digital: 150 ms

This limits tune command rate while searching without changing analog tuning
responsiveness.

### 5. Hold anchor

When a digital hold first becomes active, Qt captures the AstraRX-confirmed:

- center frequency,
- offset frequency,
- receiver frequency.

After cancelling local pending work, Qt emits exactly one
`SpectrumGLPlot.digital_hold_anchor` offset command. Because this command is
queued after any already-emitted drag/scan command on the Qt->AstraRX
WebSocket, it makes the synchronized NCO position the final client command.

### 6. Central C++ safety net

`Mainwindows::sendmessage()` stores the latest digital voice state and blocks a
pure `dspcontrol` `offset_freq` command when the same digital mode is locked.
This catches frequency writers outside `SpectrumGLPlot.qml` as well.

It does not block:

- full demod messages containing `mod`,
- `setfrequency`,
- explicit manual requests,
- preset/memory requests,
- `LogDeviceScanner` explicit requests,
- the R19.6 hold-anchor command.

Therefore the operator can still deliberately leave a call using an explicit
frequency/preset action.

## Runtime diagnostics

Expected markers:

- `[R19.6 DIGITAL TUNE HOLD]`
- `[R19.6 DIGITAL OFFSET CANCEL]`
- `[R19.6 DIGITAL FREQ RESTORE]`
- `[R19.6 DIGITAL HOLD ANCHOR]`
- `[R19.6 DIGITAL SCAN BLOCK]`
- `[R19.6 DIGITAL TX BLOCK]`

During stable D-Star voice, there should no longer be a continuous stream of:

`[QT5-FREQ-TX] ... client_source=SpectrumGLPlot.offset ...`

## Acceptance test

1. Start AstraRX R19.5 and Qt R19.6.
2. Select D-Star and tune until AstraRX reports `sync=1` and `mbe_fps` around 50.
3. Leave the receiver on the call for at least 30 seconds.
4. Confirm `sync_losses` does not increase due to UI offset movement.
5. Confirm PCM8/PCM48 continuity remains near 8 kSPS / 48 kSPS while speech is active.
6. Drag the spectrum cursor during active voice. The RF frequency must remain held and R19.6 should log a hold/block event.
7. After voice/sync releases, drag again. Only one digital offset request should be committed on release.
8. Verify analog tuning/drag behavior remains unchanged.

## Scope

AstraRX R19.5 DSP, Digiham, CodecServer, R19.4 HQ PCM SRC, R19.5 Qt single ALSA
owner, R18 native FFT renderer and R13 crash diagnostics are unchanged.
