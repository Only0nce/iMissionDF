# R20.4-SPECTRUM-CUDA1.18-RF-CALIBRATED-SPECTRUM-Y-AXIS

## Purpose

Correct the Spectrum Y-axis presentation so a tuned signal visually agrees with the AstraRX RF LEVEL while preserving the original Intensity Scale behavior.

This revision is derived surgically from CUDA1.17. It keeps the CUDA1.17 18 px grid/trace geometry correction, but **reverts the CUDA1.17 fixed independent Spectrum range** because the user requires Intensity Min/Max to continue controlling Spectrum and Waterfall exactly as before.

## User-visible problem

A representative field observation was:

```text
RF LEVEL ~= -86 dBm
visible Spectrum peak ~= -100 to -90 on the old dBFS Y axis
```

The Spectrum geometry could be internally consistent while still looking wrong to the operator because AstraRX S-meter and raw FFT dBFS are different references.

## Design contract

### Preserved Intensity Scale

The same existing values continue to drive both renderers:

```text
waterfallMinDb / waterfallMaxDb
        |                 |
        +--> Spectrum     +--> Waterfall
```

Manual Intensity adjustment and existing Waterfall auto-scale behavior are preserved. No fixed `spectrumMinDb/spectrumMaxDb` range is introduced.

### Shared plot geometry retained

The CUDA1.17 top-inset correction remains:

```text
plotTop    = 18 px
plotBottom = itemHeight
plotHeight = plotBottom - plotTop
```

The QML grid and C++ native Spectrum trace therefore still use identical vertical geometry.

### RF-reference calibration

Raw FFT data remains unchanged in dBFS.

A low-rate presentation-only offset is estimated from:

```text
candidateOffsetDb = AstraRX_SMeter_dB - selected_FFT_dBFS
```

The candidate is accepted only when:

- receiver S-meter has passed the existing 120 ms tuning settle guard,
- selected FFT measurement is valid,
- selected FFT-domain SNR >= 4 dB,
- candidate is finite and within +/-60 dB.

First trustworthy candidate establishes the reference immediately. Later updates use a bounded EMA:

- per-sample error limited to +/-3 dB,
- alpha 0.08 when selected SNR >= 12 dB,
- alpha 0.03 otherwise.

This keeps the Y-axis visually stable and prevents normal frame-to-frame FFT/S-meter jitter from moving the complete scale.

The offset is **not** applied to the FFT buffers, Max Hold data, Waterfall history, CUDA kernels, receiver tuning, or DSP.

## Spectrum Y-axis mapping

Rendering still uses the raw Intensity range. Labels are translated into the RF-referenced domain.

For a displayed RF-axis tick:

```text
rawDb = displayedRfDb - calibrationOffsetDb

y = plotBottom
  - ((rawDb - rawMinDb) / (rawMaxDb - rawMinDb)) * plotHeight
```

Ticks are generated at clean 10 dB RF values (`-110`, `-100`, `-90`, `-80`, etc.) rather than simply adding a fractional offset to old tick labels.

Before calibration is valid, the axis truthfully falls back to raw `dBFS` labels.

## Sticky metrics HUD

- `RF LEVEL` = AstraRX tuned receiver S-meter (existing project dBm convention)
- `SPECTRUM` = selected FFT level + current visual calibration offset
- `NOISE` = local FFT noise + current visual calibration offset
- `SNR` = selected FFT level - local FFT noise; unchanged pure difference in dB

After calibration, Spectrum and Noise are displayed in the same RF-referenced dBm presentation as the Y-axis. Before calibration they fall back to raw dBFS.

## Telemetry

Every ~5 seconds the existing RF metrics log now includes:

```text
[RF-METRICS]
freq=...
astra_smeter=...
fft_point_raw=...
fft_local_noise_raw=...
fft_snr=...
axis_cal_valid=1
axis_cal_db=...
spectrum_rf=...
noise_rf=...
bw=...
low_cut=...
high_cut=...
```

This makes it possible to verify the relationship on the Jetson without guessing an offset.

## Target validation

1. Build and run on the Jetson Qt 5.15.2 target.
2. Tune to a stable carrier with SNR > 4 dB.
3. Confirm `RF LEVEL` receives the AstraRX value.
4. After calibration becomes valid, check that the same carrier lies near the corresponding RF-referenced Y-axis value. Example: RF LEVEL around `-86 dBm` should visually lie around `-86 dBm`, i.e. between the `-90` and `-80` grid lines.
5. Adjust Intensity Min/Max. Spectrum vertical zoom/range must still respond exactly as before; Waterfall must also continue responding.
6. Confirm the Y-axis grid stays aligned with the green trace after Intensity changes.
7. Confirm red Max Hold, Waterfall, zoom/pan, sticky lock, Scan/Memory and FPS telemetry still operate normally.
8. Capture `[RF-METRICS]` lines from several signals/bandwidths to evaluate how stable the calibration offset is in real hardware.

## Build note

The CUDA shared library does not need rebuilding. The main `iScanMR10` application must be rebuilt because `FftDisplayItem.cpp/.h` changed.
