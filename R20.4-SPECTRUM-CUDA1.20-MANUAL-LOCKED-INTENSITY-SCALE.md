# R20.4-SPECTRUM-CUDA1.20-MANUAL-LOCKED-INTENSITY-SCALE

## Goal
Restore the original operator-controlled Intensity Min/Max behavior while preventing the Spectrum Y-axis and Waterfall intensity range from drifting automatically.

## Correct behavior
- Intensity Min/Max sliders remain adjustable at any time.
- Manual values are authoritative and remain where the operator places them.
- Auto-scale is OFF by default and the 500 ms auto-scale timer cannot change the range while locked.
- Spectrum and Waterfall share the same raw dBFS Min/Max range again.
- The one-time AstraRX S-meter calibration offset remains latched for the backend session.
- RF calibration changes only Spectrum Y-axis labels and displayed calibrated Spectrum/Noise values; raw FFT samples and geometry are unchanged.
- The corrected shared `plotTop=18 px` geometry from CUDA1.17 remains in place.

## Why CUDA1.19 was wrong
CUDA1.19 stabilized the axis by replacing the operator range with a fixed Spectrum-only range. That stopped drift, but also made the Intensity control unable to change the Spectrum vertical scale. This was the wrong layer to lock.

## Architecture
```
Operator Intensity Min/Max
        |
        +--> Spectrum raw min/max
        +--> Waterfall raw min/max

Auto-scale timer
        X  disabled/guarded while locked

AstraRX RF LEVEL + selected FFT
        |
        +--> one-time median-5 calibration offset (latched)
                 |
                 +--> Spectrum Y labels only
                 +--> calibrated Spectrum/Noise HUD values
```
