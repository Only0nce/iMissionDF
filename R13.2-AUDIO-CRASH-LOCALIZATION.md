# R13.2 Audio Crash Localization

R13.2 is instrumentation-only on top of R13.1. It does not intentionally change Qt/QML, AstraRX frequency, codec, recorder, or ALSA playback behavior.

Two observed failures had the same signature: SIGSEGV/SEGV_MAPERR, fault address 0x100, main-thread TID==PID, with the previous thread checkpoint AUDIO_PUSH. Because R13 checkpoints are sticky, AUDIO_PUSH only proved that pushAudio() was the last instrumented main-thread path; it did not prove the fault occurred inside that function.

R13.2 therefore splits pushAudio into checkpoints:
- 310 AUDIO_PUSH (entry)
- 311 AUDIO_PUSH_BEFORE_LOCK
- 312 AUDIO_PUSH_LOCKED
- 313 AUDIO_PUSH_TRIM
- 314 AUDIO_PUSH_ENQUEUE
- 315 AUDIO_PUSH_WAKE
- 316 AUDIO_PUSH_DONE
- 207 WS_AUDIO_POST_PUSH (caller regained control after pushAudio)

The fatal handler also records AArch64 FP/LR and X0-X3 in addition to PC/SP. This helps distinguish a null/near-null object/member dereference from a crash after returning to the WebSocket/QML path.

After a failure:

    tail -n 250 /tmp/iScanMR10-debug.log
    ./RESOLVE-R13-PC.py /tmp/iScanMR10-debug.log

If the checkpoint is 311-315, focus inside AlsaAudioPlayer::pushAudio. If it is 316 or 207, pushAudio completed and the fault is downstream. If it is another checkpoint, follow that subsystem instead.
