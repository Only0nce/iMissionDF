# R20.4 Native FFT / QV4 Pressure Hardening

## Objective

R20.4 continues directly from R20.3. The ARM64 QV4 interpreter safety guard remains enabled by default on Jetson. This revision removes the high-rate FFT data path from the QML/JavaScript heap while preserving the existing Spectrum/Waterfall appearance, frequency mapping, Max Hold behavior, Peak Scan behavior, audio path, network path, and user interaction.

## Why this revision exists

The native core dump showed the fatal SIGSEGV inside `QV4::MemoryManager::collectFromJSStack()`. R20.3 contains the immediate JIT-risk workaround. R20.4 additionally reduces the amount of FFT-sized JavaScript data that the QV4 garbage collector must manage.

Before R20.4 the production display path was:

```text
AstraRX FFT
  -> WebSocketClient
  -> QVariantList (up to full FFT size)
  -> Mainwindows signal
  -> QML JavaScript array
  -> Spectrum Canvas
  -> Waterfall Canvas
```

R20.4 production path:

```text
AstraRX FFT
  -> WebSocketClient native validation
  -> full-resolution QVector<float>
       |-> exact native Max Hold / Peak Scan state
       |-> native auto-scale statistics
       |-> Spectrum display QVector (default <= 8192)
       |-> Waterfall peak-pooled QVector (default <= 1280)
  -> FftDisplayItem (QQuickPaintedItem)
```

No FFT-sized QVariantList is sent into QML in the default production path.

## Compatibility / UX rules

R20.4 does not intentionally modify:

- layout, anchors, dimensions, fonts, icons, colors or control placement;
- frequency ownership or AstraRX tuning protocol;
- zoom/pan formulas;
- Spectrum line color and one-pixel line width;
- Max Hold color/enable/clear behavior;
- Waterfall color map or dB scale policy;
- Peak Scan full-resolution Max Hold snapshot;
- audio, ALSA, volume, recorder, network, Wi-Fi or 5G behavior.

The static grid and interactive overlay remain QML Canvas items because they are not high-rate FFT data consumers.

## Native renderer

`FftDisplayItem` is registered as:

```qml
import iScan.Display 1.0
```

Two instances are used:

- `FftDisplayItem.Spectrum`
- `FftDisplayItem.Waterfall`

The existing IDs `spectrumCanvas` and `waterfallCanvas` are retained to minimize behavioral changes in the surrounding QML logic.

## FFT ingress validation

R20.4 restores the native R17 validation policy:

- uncompressed payload must be aligned to `sizeof(float)`;
- bin count must be greater than zero;
- bin count must not exceed `ISCAN_FFT_MAX_BINS` (default 65536);
- when strict mode is enabled and AstraRX supplies `fft_size`, received bin count must match it;
- NaN/Inf frames are rejected as a whole.

Defaults:

```text
ISCAN_FFT_STRICT_SIZE=1
ISCAN_FFT_MAX_BINS=65536
```

## Display budgets

Defaults:

```text
Spectrum:  ISCAN_SPECTRUM_DISPLAY_BINS=8192
Waterfall: ISCAN_WATERFALL_DISPLAY_BINS=1280
```

An 8192-bin source Spectrum is preserved exactly. Larger frames are peak-pooled only for display transport. Full-resolution native data remains available for Max Hold/Peak Scan.

Waterfall uses peak pooling rather than averaging so a narrow carrier is not averaged away.

## Auto scale

The old QML path sampled up to 512 FFT values, created a JavaScript array and sorted it every 500 ms.

R20.4 performs the same bounded median / 99.5-percentile calculation in C++ and exposes only:

```text
wsClient.fftNoiseDb
wsClient.fftStrongDb
wsClient.fftAutoScaleValid
```

The existing QML smoothing and min/max range policy remain unchanged.

## Legacy diagnostic bridge

The full FFT QVariant/QML bridge remains available only for controlled A/B diagnostics:

```bash
export ISCAN_FFT_QML_PUBLISH=1
```

Default:

```text
ISCAN_FFT_QML_PUBLISH=0
```

Do not enable this for the normal R20.4 soak test.

## R20.3 safety guard retained

Jetson still defaults to:

```text
QV4_FORCE_INTERPRETER=1
```

unless the engineering A/B override is explicitly set:

```text
ISCAN_QML_JIT=1
```

For the R20.4 stability test, leave both overrides unset so interpreter mode is active and the QML FFT bridge remains disabled.

## Expected startup markers

```text
[R20.3 QML-JIT-SAFETY] revision=20260909-arm64-qv4-interpreter-no-ui
[R20.4 NATIVE FFT] revision=20260909-native-fft-qv4-pressure-no-ui
[R20.4 FFT Runtime] qmlPublish= false strictSize= true ... renderer=native-qquickpainteditem
[QML ENGINE] QV4_FORCE_INTERPRETER= 1
```

## Target test

1. Build with the same Qt5Orin kit used for the existing application.
2. Confirm the startup markers above.
3. Verify Spectrum/Waterfall appearance against R20.3.
4. Verify zoom, pan, frequency cursor, click/drag tuning and Max Hold.
5. Verify Peak Scan still detects the same carriers.
6. Exercise Network/Wi-Fi/5G and 5G Restart while audio is active.
7. Exercise analog and digital modes and volume controls.
8. Soak for at least 6 hours; 12-24 hours is preferred.
9. If a fatal signal occurs, preserve the R13 debug log and run the same core diagnostic capture.
