# R16.1 QML Connection Hardening

## Why
R16 still reproduced SIGSEGV at the same Qt5Qml instruction signature (`+0xB9A94`, fault address `0x100`).
The captured core has an actual `/memfd:JITCode:QtQml` frame in the main-thread frame-pointer chain, so the active crash path is still inside QML/JavaScript execution.

## Changes
- Removed remaining executable JavaScript `.connect()` calls from QML source.
- Replaced them with lifecycle-scoped `Connections` objects in:
  - `RadioScanner.qml`
  - `FindBandsWithProfile.qml`
  - `HomeDisplay.qml`
  - `Wifi5GSetting.qml`
  - `Setting.qml`
- Preserved existing signal behavior and handlers.
- Added WebSocket checkpoints:
  - 208 `WS_AUDIO_BRANCH_DONE`
  - 209 `WS_BINARY_RETURN`
  These distinguish a crash inside audio packet handling from a later QML/event-loop crash.

## Diagnostic A/B
If the same crash remains, run one soak test with `QV4_FORCE_INTERPRETER=1` before process start. This disables QML JIT for isolation only; it is not the intended production setting because it can reduce UI performance.
