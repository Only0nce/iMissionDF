# R20.4-SPECTRUM-CUDA1 — Smooth GPU/CUDA Spectrum & Waterfall

Baseline: `R20.4-SPECTRUM-A3`

Scope is intentionally limited to the Spectrum/Waterfall rendering subsystem and its build metadata. No Audio, ALSA, Network, WiFi, 5G, Recorder, AstraRX frequency ownership, Mainwindows runtime control, or QML interaction flow is changed.

## Goals

1. Reduce Qt GUI/main-thread work while Spectrum/Waterfall is active.
2. Move Waterfall peak-pooling, palette mapping, and retained-history recoloring to CUDA on Jetson Orin.
3. Remove the per-frame multi-megabyte Waterfall history `memmove()`.
4. Keep latency bounded by coalescing old FFT rows when compute is busy.
5. Preserve R20.4/R20.3 stability: CUDA failure must never terminate iScanMR10.
6. Preserve the Astra-style A3 UX/UI exactly.

## Runtime architecture

```text
AstraRX FFT
    |
    v
WebSocketClient (unchanged)
    |
    v
FftDisplayItem
    |
    +--> Spectrum path (native C++, QPainter/FBO)
    |
    +--> Waterfall request
             |
             v
      SpectrumCudaWorker thread
             |
             +--> CUDA plugin available
             |       |
             |       +-- peak pooling
             |       +-- dB -> palette LUT
             |       +-- full-history recolor
             |
             +--> CUDA unavailable/error
                     |
                     +-- CPU worker fallback
             |
             v
      processed row / recolored history
             |
             v
      ring-buffer history
             |
             v
      Qt Quick FBO/OpenGL paint on Jetson
```

No `cudaStreamSynchronize()` runs on the Qt GUI thread.

## Important changes

### 1. Waterfall ring buffer

A3 shifted the complete Waterfall image and dB history every new row. CUDA1 stores rows in a circular buffer. Newest-to-oldest display order is reconstructed as at most two contiguous source segments during paint.

This removes the previous `memmove()` of several MiB per Waterfall update.

### 2. Async compute worker

Only one row/recolor operation is allowed in flight. If new rows arrive while compute is busy, the newest row replaces the previous pending row.

This is intentional for a realtime receiver: fresh RF data is more valuable than growing display latency.

### 3. CUDA plugin

The Qt application does not directly link CUDA. `SpectrumCudaProcessor` dynamically loads:

```text
/opt/iScanMR10/lib/libiscan_spectrum_cuda.so
```

Search order also supports:

```text
ISCAN_SPECTRUM_CUDA_LIB=<path>
<app-dir>/libiscan_spectrum_cuda.so
<app-dir>/../lib/libiscan_spectrum_cuda.so
/usr/local/lib/libiscan_spectrum_cuda.so
```

This keeps the existing Qt Creator AArch64 cross-build unchanged.

### 4. CUDA operations

CUDA currently accelerates:

- Full-axis Waterfall peak pooling.
- dB -> 1024-entry palette LUT conversion.
- Recolor of retained dB history when Min/Max/palette changes.

The small 5 Hz Peak/Noise/SNR metrics remain CPU-native because CUDA launch/transfer overhead would not be justified.

### 5. FBO/OpenGL painting

On Jetson, `QQuickPaintedItem::FramebufferObject` is the default render target. Disable only for A/B diagnostics:

```bash
export ISCAN_SPECTRUM_FBO=0
```

### 6. CUDA failure policy

If the plugin is missing, fails to initialize, or returns a runtime CUDA error:

```text
CUDA -> disabled for this process
CPU-worker -> continues
UI -> continues
Audio -> unaffected
Application -> must not terminate
```

Force CPU for A/B:

```bash
export ISCAN_SPECTRUM_CUDA=cpu
```

Use default/auto CUDA:

```bash
unset ISCAN_SPECTRUM_CUDA
```

## Building the Qt application

Use the same Qt Creator / qmake Jetson kit as R20.4/A3. CUDA is not part of the Qt link step.

Expected qmake changes are only the additional C++ worker/loader sources.

## Building the CUDA plugin on Jetson Orin

Copy these files to the target:

```text
SpectrumCudaKernels.cu
build_spectrum_cuda_plugin.sh
```

Then on Orin:

```bash
chmod +x build_spectrum_cuda_plugin.sh
./build_spectrum_cuda_plugin.sh --install
```

Default target GPU architecture:

```text
sm_87
```

Override only for another target:

```bash
ISCAN_CUDA_ARCH=sm_XX ./build_spectrum_cuda_plugin.sh --install
```

Verify:

```bash
file /opt/iScanMR10/lib/libiscan_spectrum_cuda.so
ldd /opt/iScanMR10/lib/libiscan_spectrum_cuda.so
```

The plugin should be an AArch64 shared object on Jetson.

## Expected application log

CUDA active:

```text
[R20.4-SPECTRUM-CUDA1] asyncComputeWorker=1 waterfallRingBuffer=1 ...
[SPECTRUM-CUDA] backend= "cuda-plugin" cudaActive= true ...
[SPECTRUM-COMPUTE-10S] backend= "cuda-plugin" cudaRows= ... cpuRows= 0 ...
```

CPU fallback:

```text
[SPECTRUM-CUDA] backend= "cpu-worker" cudaActive= false ...
```

Runtime CUDA failure:

```text
[SPECTRUM-CUDA] runtime fallback to CPU: ...
```

This is a degraded mode, not a fatal error.

## Test plan

1. Confirm visual output is identical to A3: Spectrum colors, Waterfall palette, HUD, scale, zoom/pan and persistent history.
2. Keep Analog audio active while opening Spectrum/Waterfall.
3. Zoom/pan repeatedly while Waterfall runs.
4. Exercise Auto Scale; verify no periodic UI/audio stall while retained history recolors.
5. Observe `tegrastats` and the 10-second compute telemetry.
6. Force CPU with `ISCAN_SPECTRUM_CUDA=cpu` and compare responsiveness/CPU.
7. Restore CUDA and soak test for 6-24 hours.
8. If any terminate occurs, capture the existing `iscan_diag.sh monitor` bundle.

## Next GPU phase

CUDA1 deliberately does not introduce CUDA/OpenGL interop. The next phase should migrate the Spectrum line from QQuickPaintedItem to QSGGeometry/VBO and the Waterfall to a GPU texture/shader. After that is stable, CUDA/OpenGL shared buffers can remove the remaining GPU->CPU->GPU copy.
