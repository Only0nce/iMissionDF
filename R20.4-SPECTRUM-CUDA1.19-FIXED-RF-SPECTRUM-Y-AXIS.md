# R20.4-SPECTRUM-CUDA1.19-FIXED-RF-SPECTRUM-Y-AXIS

## Goal
Stop the Spectrum Y-axis from continuously moving while preserving the existing Waterfall Intensity control and RF measurement behavior.

## Root cause in CUDA1.18
Two independent live feedback loops changed the Spectrum axis:

1. `autoScaleWaterfallColor()` continuously changed `waterfallMinDb/waterfallMaxDb` (500 ms cadence), and CUDA1.18 reused those values for the Spectrum amplitude range.
2. `onSmeterValueUpdated()` continuously EMA-updated `m_spectrumCalibrationOffsetDb`, so even the displayed dBm labels drifted with S-meter/FFT jitter.

Both are valid ideas separately, but together they made the Spectrum scale visibly breathe.

## CUDA1.19 architecture

### Spectrum
- Fixed displayed RF axis: **-150 .. -20 dBm** after calibration lock.
- Before RF calibration is available, use the same fixed span as **-150 .. -20 dBFS**.
- Preserve the CUDA1.17 shared `plotTopInset = 18 px` geometry fix.
- Raw FFT samples are never modified.

### RF calibration
- Use AstraRX S-meter minus selected FFT level as the calibration candidate.
- Accept only sane candidates (`-60 .. +60 dB`) with selected FFT SNR >= 4 dB.
- Collect **5 trusted candidates**.
- Latch the **median** once.
- Hold that offset for the full backend session; no EMA, no continuous update.
- Reset only when the backend session changes/restarts.

This deliberately prefers a stable instrument scale over chasing sub-dB live calibration error.

### Waterfall Intensity
- `waterfallMinDb/waterfallMaxDb`, Auto Scale, and manual `WaterfallScaleControl` remain unchanged.
- They affect Waterfall presentation only.
- They no longer repaint/redefine Spectrum Y-axis labels.

## Measurement contract
- `RF LEVEL`: AstraRX tuned-receiver S-meter.
- `SPECTRUM`: selected FFT level + latched RF calibration offset.
- `NOISE`: local FFT noise + same latched offset.
- `SNR`: pure FFT-domain difference; offset cancels.

## Runtime files changed
- `FftDisplayItem.h`
- `FftDisplayItem.cpp`
- `SpectrumGLPlot.qml`

## Not changed
- CUDA plugin ABI/kernels
- FFT frame generation
- Max Hold data
- Waterfall history/palette
- Scan/Memory workspace
- Audio/network/frequency transaction logic


## Expected telemetry after lock
```text
[RF-METRICS] ... axis_cal_valid=1 axis_cal_latched=1 axis_cal_samples=5 axis_cal_db=...
```

After `axis_cal_latched=1`, `axis_cal_db` must remain constant for the backend session.
