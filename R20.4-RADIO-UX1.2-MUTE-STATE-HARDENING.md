# R20.4 RADIO UX1.2 — Mute State Ownership Hardening

Base: NET-ENDPOINTS1.3 restored-top-drawer source.

## Problem
On the main radio UI, pressing the speaker mute control could make the mute icon/state disappear or become inconsistent. The asset itself was present in qrc; the issue was state ownership.

The current QML had multiple mute-state writers:
- `HomeDisplay.scanMuteOn` was intended to be authoritative.
- `MyDrawer` mirrored `wsClient.mutedChanged` into `scanMuteOn`.
- `VolDrawer` imperatively assigned its externally-bound `mute` property to `false` from a slider/progress callback, breaking the QML binding.
- speaker/headphone/software-volume state handlers in `HomeDisplay` also explicitly called `setSpeakerVolumeMute(0)`, allowing volume changes to clear mute unexpectedly.
- the Main-page `Speaker` label did not display mute state.

## Fix
### Single mute state owner
`HomeDisplay` now owns backend mute readback:
- initial state is synchronized from `wsClient.muted` in `Component.onCompleted`;
- a lifecycle-scoped `Connections { target: wsClient }` updates `scanMuteOn` from `mutedChanged`.

The duplicate `MyDrawer` mutedChanged listener was removed.

### Passive drawers
`VolDrawer` and `VolumeDrawer` no longer write their externally-bound `mute` property. They only emit `muteToggleRequested()` and render the icon from the parent-provided state.

### Volume adjustment does not clear mute
Removed implicit unmute calls from:
- software volume (`scanAudioLevel`),
- speaker volume (`scanVolLevel`),
- headphone volume (`scanVolLevelHeadphone`).

Squelch-specific unmute behavior in `onScanSqlLevelChanged` is intentionally preserved to avoid changing the existing SQL policy.

### Main-page status
The `Speaker` button now displays:
- `Speaker / Mute` when muted,
- the existing dB value when unmuted.

## Preserved behavior
- `MyDrawer.toggleVolumeMute()` still performs the existing mute + SQL transaction.
- `WebSocketClient::setSpeakerVolumeMute()` is unchanged.
- speaker/headphone volume ranges and hardware channels are unchanged.
- software-volume algorithm is unchanged.
- LAN / Endpoints / WiFi / 5G / VPN and restored Top Network Drawer are unchanged.

## Runtime acceptance sequence
1. Open Main page and Speaker Volume drawer.
2. Press speaker mute.
3. Confirm `speaker_mute.png` remains visible and Main Speaker reads `Mute`.
4. Close and reopen the drawer; mute state must remain.
5. Move speaker, headphone, and software-volume controls; mute must remain active.
6. Press mute again; icon must return to `speaker.png` and Main Speaker must show dB.
7. Verify normal volume changes still reach existing backend/hardware paths.

## Build status
The artifact environment does not contain the target Qt/qmake toolchain, so this revision is structurally validated only. Build and runtime test on the normal Qt 5.15 Jetson/dev host are still required.
