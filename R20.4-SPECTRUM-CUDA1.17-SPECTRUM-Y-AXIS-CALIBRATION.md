# R20.4-SPECTRUM-CUDA1.17-SPECTRUM-Y-AXIS-CALIBRATION

## Purpose

Correct the Spectrum Y-axis so the native FFT trace, Y-grid labels, and FFT-domain HUD values share one amplitude/geometry contract.

This revision is derived surgically from CUDA1.16. It does not change the AstraRX protocol, FFT source data, CUDA worker/plugin, waterfall history, audio, tuning ownership, Scan/Memory, or FPS60 presentation architecture.

## Root causes fixed

1. **Spectrum and Waterfall shared the same min/max state.** Waterfall auto-scale therefore changed the Spectrum amplitude axis even though Waterfall min/max are a color/intensity concern.
2. **Native trace and QML grid used different vertical geometry.** The C++ trace used `height - 18` but mapped max dB to `y=0`; the QML grid used full height. This created up to an 18 px vertical disagreement.
3. **Receiver RF level and Spectrum amplitude were visually mixed.** AstraRX S-meter is shown using the project's dBm convention, while the Spectrum data is dBFS. CUDA1.17 labels these as separate measurement domains.

## New Spectrum scale

- `spectrumMinDb = -150 dBFS`
- `spectrumMaxDb = -20 dBFS`
- `spectrumPlotTopPx = 18 px`

Waterfall continues to use independent `waterfallMinDb` / `waterfallMaxDb` and its existing auto-scale behavior.

## Shared vertical mapping

For both QML grid and native C++ Spectrum renderer:

```text
plotTop    = 18 px
plotBottom = itemHeight
plotHeight = plotBottom - plotTop

y(db) = plotBottom
      - ((db - spectrumMinDb) / (spectrumMaxDb - spectrumMinDb))
        * plotHeight
```

Therefore:

- `spectrumMaxDb` maps exactly to `plotTop`
- `spectrumMinDb` maps exactly to `plotBottom`
- intermediate dBFS values map to the same pixel in both render paths

The green fill is also closed at `plotBottom`, and its gradient spans the same plot region.

## Sticky metrics HUD

The HUD now makes the domains explicit:

- `RF LEVEL` = AstraRX tuned-receiver S-meter, shown with the existing project dBm convention
- `FFT LEVEL` = selected-frequency FFT value in dBFS; this is the value that belongs on the Spectrum Y-axis
- `NOISE` = local selected-frequency FFT noise floor in dBFS
- `SNR` = FFT LEVEL - local FFT NOISE, in dB

`RF LEVEL` is never subtracted from dBFS values.


## Hardware validation

1. Build and run on the Jetson Qt 5.15.2 target.
2. Confirm the runtime marker above.
3. Move the selected receiver to a visible carrier.
4. Compare `FFT LEVEL` with the green trace against the Y-grid. For example, approximately `-100 dBFS` must visually sit near the `-100 dBFS` grid line.
5. Change Waterfall Min/Max or allow Waterfall auto-scale to operate. The Spectrum Y-axis and trace vertical scale must not move as a side effect.
6. Confirm `RF LEVEL` can differ numerically from `FFT LEVEL`; this is expected because dBm and dBFS are different domains.
7. Verify Max Hold, zoom/pan, selection, sticky lock, Waterfall history, and FPS telemetry remain operational.

## Build note

The CUDA shared library does not need rebuilding. `FftDisplayItem.cpp/.h` changed, so the main `iScanMR10` application must be rebuilt.
