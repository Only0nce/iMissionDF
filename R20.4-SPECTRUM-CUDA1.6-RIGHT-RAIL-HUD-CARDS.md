# R20.4-SPECTRUM-CUDA1.6-RIGHT-RAIL-HUD-CARDS

## Scope

This revision is a QML-only UX/layout refinement derived from `R20.4-SPECTRUM-CUDA1.5-WATERFALL-FOCUS`.
It does not change FFT/CUDA processing, native rendering, AstraRX protocol, audio, network, 5G, recorder, frequency ownership, or the floating Scan/Memory workspace logic.

## Changes

### 1. Separate translucent HUD cards

The lower Waterfall controls are no longer completely transparent and are not wrapped by one large opaque pod.
Each functional group has its own low-opacity gray card:

- Analog bandwidth
- Max Hold
- RF S-meter
- Waterfall intensity scale

The card fill is `Qt.rgba(0.36, 0.39, 0.42, 0.30)` with a subtle border. Control/text opacity remains 1.0 for legibility.

### 2. Longer data-driven Waterfall legend

The right-side Waterfall color legend now uses the available vertical space dynamically. Its height reserves deterministic space for:

- the bottom Waterfall HUD dock
- the vertical Scan/Memory toggle rail
- a safety gap

This allows a substantially longer color bar without colliding with the bottom S-meter/intensity cards.

### 3. Scan/Memory moved to the Waterfall right rail

The center-bottom Scan/Memory launcher is removed. The same toggle actions are now stacked vertically immediately below the color legend:

- `SCAN`
- `MEMORY`

The rail stays visible while a floating workspace is open. Pressing the active mode again closes the floating workspace; pressing the other mode switches content directly.

## Preserved contracts

- Spectrum/Waterfall ratio remains 42/58.
- CUDA1.1/FPS60 pipeline unchanged.
- CUDA plugin ABI and kernels unchanged.
- Persistent full-axis Waterfall history unchanged.
- Sticky Peak/Noise/SNR selection metrics unchanged.
- Floating workspace remains non-modal and persistent.
- Existing `LogDeviceScanner` and `NewMemoryAddEdit` remain the only Scan/Memory implementations.
- Peak Scan behavior unchanged.

## Files changed

- `SpectrumGLPlot.qml`
- `BandwidthScaleControl.qml`
- `WaterfallScaleControl.qml`
