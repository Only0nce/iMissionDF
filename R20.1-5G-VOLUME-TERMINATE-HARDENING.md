# R20.1 5G / Volume / Terminate Hardening — No Visual UI Change

Revision: `20260909-5g-volume-diagnostics-no-ui`

## Field symptoms addressed

1. During 5G reset, AstraRX audio stutters or nearly disappears.
2. The existing Restart button remains in `Restarting` after modem recovery appears complete.
3. The application can later terminate; a similar volume/QML lifetime issue had previously been hardened in R15/R16 but parts of that implementation were no longer active in the R20 source baseline.

## Changes

### 5G reset isolation

`NetworkController` cellular realtime status polling is suspended only while the 5G reset transaction is active. Requests arriving during reset are remembered but cannot restart the synchronous timer until recovery finishes. Polling is restored at the same prior interval after completion without an immediate main-thread status probe. This prevents synchronous modem/status probes on the Qt main thread from starving the AstraRX WebSocket audio ingress.

The successful reset path no longer runs the heavy 5G diagnostic dump. Failure diagnostics are now collected by a detached process into `/tmp/iScanMR10-5g-reset-debug.log`, so diagnostics cannot delay the transaction result either. `reset5GModemFinished()` is emitted before realtime status polling is resumed, so the existing QML button state can return from `Restarting` promptly.

No QML layout, style, text, navigation, or button contract is changed.

### R15 volume ownership restored

- `HomeDisplay` remains the only authoritative QML volume state.
- Rotary changes only the authoritative state; it no longer imperatively writes drawer properties.
- `MyDrawer` uses user-only `Slider.moved` rather than `valueChanged` for volume writeback.
- Child drawers request mute changes instead of mutating externally bound mute state.
- `MyDrawer` is the single owner of the existing mute + squelch policy.
- C++ speaker/headphone getters report requested values matching the actual setter paths.
- Legacy speaker effective policy (`requested < 165 -> CH4=50`) is preserved.

Visual UI and intended user controls are unchanged.

### R16/R16.2 diagnostics restored to active build

`CrashDiagnostics.cpp/.h` are back in the qmake graph. The application again records fatal signal, external SIGTERM/SIGINT sender information, `std::terminate`, checkpoints, and Qt event-dispatch context. This is diagnostic-only and does not change normal application behavior.

## Expected validation

- While listening to AstraRX audio, trigger 5G Restart. Audio may still experience a small hardware/CPU disturbance, but should no longer suffer long stalls caused by synchronous 5G status polling.
- The existing Restart button should return after the backend recovery result, before background status polling resumes.
- Exercise rotary speaker/headphone/software volume repeatedly; state should converge without QML binding writeback loops.
- If the application terminates, preserve `/tmp/iScanMR10-debug.log`; it should now distinguish `R13-FATAL`, `R13-TERM`, and `std::terminate` paths.
