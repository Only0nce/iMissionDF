# R20.4 RADIO UX1.3 — Volume/Speaker Adjustment Clears Mute

Base: R20.4 RADIO UX1.2 Mute State Ownership Hardening.

## Requirement
When the receiver is muted, a deliberate user increase/decrease of either the software **Volume** or hardware **Speaker** level must clear mute so the speaker icon returns to its normal state.

## Behavioral contract

Muted + user adjusts Volume/Speaker:

1. Request backend speaker unmute (`setSpeakerVolumeMute(0)`).
2. Preserve the established unmute-side SQL transaction used by the mute button.
3. Wait for the backend `mutedChanged(false)` readback.
4. `HomeDisplay.scanMuteOn` becomes false.
5. `speaker_mute.png` returns to `speaker.png` and Main-page Volume/Speaker text returns from `Mute` to the numeric level.

This applies to:
- Volume slider movement.
- Speaker slider movement.
- Rotary CW/CCW while the selected profile is Volume.
- Rotary CW/CCW while the selected profile is Speaker.

This does **not** apply to Headphone adjustment.

## Architecture
`HomeDisplay.scanMuteOn` remains the single UI mute-state owner. Child drawers never assign `mute=false` directly.

A new `unmuteFromUserVolumeAdjustment()` helper performs the same backend unmute transaction as the explicit mute button. A short pending guard avoids flooding the backend with repeated unmute requests while a slider is moving and before `mutedChanged(false)` arrives.

The helper is invoked only from actual user interaction paths, not from generic `onScanAudioLevelChanged` / `onScanVolLevelChanged` handlers. This prevents configuration restore, startup synchronization, or external state updates from accidentally clearing mute.

## Files changed
- `HomeDisplay.qml`
- `MyDrawer.qml`

No C++ audio backend, Network Settings, VPN, Endpoints, RFSoC, or database code is changed.
