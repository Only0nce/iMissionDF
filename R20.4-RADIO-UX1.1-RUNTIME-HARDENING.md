# R20.4-RADIO-UX1.1-RUNTIME-HARDENING

## Basis

Derived surgically from `R20.4-RADIO-UX1-ASTRA-SHELL` after Jetson runtime validation on 2026-09-11.

The test log showed the Radio UX itself was running, but exposed four independent runtime defects/noise sources that could interfere with interaction stability and frame pacing:

1. `LogDeviceScanner.qml:1857: Error: Invalid write to global property "pendingDSP"`
2. `QQmlVMEMetaObject: Internal error - attempted to evaluate a function in an invalid context` followed by `Wifi5GPage.qml:527 ... ensureValidSelectedPage ... is not a function`
3. Repeated `[SQL] Failed to read SHD_AMP state` during frequency/offset interaction.
4. Hundreds of false `[UnixSocket] JSON parse error` warnings for the recorder's actual CSV status protocol.
5. Duplicate attempts to start optional `irec-recover.service` when the unit is not installed.

## Changes

### 1. LogDeviceScanner tune transaction state

`LogDeviceScanner.qml` now declares the state it already used:

- `pendingDSP`
- `pendingCenterFreq`
- `pendingUIParams`
- `startDSPAfter`

The 500 ms delayed apply now consumes the click-time snapshot instead of re-reading mutable `radioMemList` state. Pending state is cleared after the transaction.

This removes the invalid-global-property runtime error and prevents a delayed preset/scan apply from picking up a different row if selection changes before the timer fires.

### 2. WiFi/5G deferred-call lifetime hardening

`Wifi5GPage.qml` no longer uses `Qt.callLater(root.syncPageRuntime)`.

A page-owned zero-delay `Timer` is used instead. It provides the same next-event-loop deferral but is destroyed/cancelled together with the page, so StackView page destruction cannot leave a callable referencing an invalid QML context.

### 3. Frequency and SQL/GPIO ownership separated again

`Mainwindows::updateCurrentOffsetFreq()` now updates frequency bookkeeping only and no longer calls `onSQLChanged()`.

`onSQLChanged()` returns before Jetson GPIO work when the SQL boolean did not actually change.

This restores the R11 contract: frequency changes do not replay squelch GPIO state. It also removes synchronous SHD_AMP/HS_MUTE/LED traffic from high-rate Spectrum tuning/drag activity.

### 4. Recorder Unix socket uses its real CSV contract

`mainwindowsiRec::onUnixSocketMessage()` no longer attempts to JSON-parse every status datagram before passing it to `deviceStatus()`.

The runtime traffic is the existing CSV contract:

```text
ip,freq,uri,ACTION
```

Examples from the test log included `GET_PARAMETER`, `SETUP`, `RECORD`, and `ANNOUNCE` messages. Removing the unused JSON parse eliminates false warnings and logging pressure without changing the authoritative CSV parser.

### 5. Optional recovery service starts once

`onVerifyUserDatabaseDone()` now:

- checks common systemd unit-file locations first,
- skips cleanly when `irec-recover.service` is not installed,
- starts it only once when present.

The previous implementation called `systemctl start irec-recover.service` twice.

## Intentionally unchanged

This revision does **not** change:

- Radio UX1 visual design
- Spectrum/Waterfall rendering code
- CUDA plugin/worker/kernels
- AstraRX WebSocket protocol
- Spectrum/Waterfall lockstep renderer
- persistent Waterfall history
- draggable divider / PAN behavior
- StackView anchor layout warning
- GPIO chip mapping
- audio queue limits
- recorder target softPhone configuration

## FPS observation from the supplied hardware log

The display reports `displayHz=60.0`, so the current 90 FPS request is correctly clamped to `effectiveFps=60`. The actual `QQuickPaintedItem` paint rate was generally about 49-55 FPS while the FFT source was about 29 FPS.

This hardening removes avoidable main-thread GPIO/logging work, which may improve pacing, but it does not claim that a 60 Hz panel can visibly present 90 FPS. If render cadence remains materially below 60 after this revision, the next performance step should target the renderer itself (Qt Scene Graph/native geometry/texture path) rather than raising timer frequency.
