# R20.4-SPECTRUM-FBO-EDGEFIX1

## Objective

Remove the one-pixel bright/rainbow fringe observed at the extreme left edge of both the native Spectrum and native Waterfall while preserving the Jetson FBO rendering path and current performance architecture.

## Evidence from the supplied screen capture

The artifact begins exactly where the analyzer native surfaces begin. Pixel inspection of the supplied 1920×1080 capture showed representative analyzer rows with:

```text
x=0   = (255,255,255)
x=1   = (45,52,58)
x=2   = (45,52,58)
```

The system/header area above the analyzer does not show the same one-pixel white edge. Because the artifact crosses both Spectrum and Waterfall, the common native `QQuickPaintedItem` FBO/scene-graph composition path is a stronger candidate than Waterfall color mapping or divider rendering.

## Production change

### 1. Preserve FBO on Jetson

The existing diagnostic override remains unchanged:

```bash
ISCAN_SPECTRUM_FBO=0 ./iScanMR10
```

The production default is still `QQuickPaintedItem::FramebufferObject` on Jetson. This revision does **not** fall back to the Image target by default.

### 2. Disable scene-graph texture smoothing on both analyzer surfaces

`SpectrumGLPlot.qml` now explicitly uses:

```qml
FftDisplayItem {
    id: spectrumCanvas
    smooth: false
}

FftDisplayItem {
    id: waterfallCanvas
    smooth: false
}
```

Both native items already paint at their destination size. Disabling linear sampling at the scene-graph composition stage prevents the edge texel from blending with texels outside the useful FBO image.

This does not disable the internal Waterfall image resampling performed by `QPainter::SmoothPixmapTransform` in `paintWaterfall()`.

### 3. Explicit transparent-black backing clear

`FftDisplayItem` now calls:

```cpp
setFillColor(QColor(0, 0, 0, 0));
```

The item remains non-opaque (`setOpaquePainting(false)`). The explicit clear contract makes unused/edge texels transparent **black**, avoiding bright RGB leakage through alpha at FBO texture boundaries.

## Runtime telemetry

The existing startup line now additionally reports:

```text
edgeSafeFill=transparent-black
sceneTextureSmooth=0
paintTarget=fbo
```

QML also emits:

```text
[R20.4-SPECTRUM-FBO-EDGEFIX1] sceneTextureSmooth=0 fill=transparent-black fboPreserved=1
```

## Hardware validation sequence

1. Rebuild and start normally with FBO enabled.
2. Confirm startup log contains `paintTarget=fbo`, `edgeSafeFill=transparent-black`, `sceneTextureSmooth=0`.
3. Inspect the extreme left edge from the start of Spectrum through the bottom of Waterfall.
4. Test with no RF data and with a live colorful Waterfall.
5. Drag the Spectrum/Waterfall divider through several ratios and verify the edge does not reappear.
6. Zoom and PAN and verify the edge remains clean.
7. Compare `[SPECTRUM-RENDER-5S]` FPS before/after. This patch should not materially reduce FPS.

### Diagnostic fallback if the fringe remains

Run once with:

```bash
ISCAN_SPECTRUM_FBO=0 ./iScanMR10
```

If the edge disappears only in `paintTarget=image`, the remaining issue is conclusively FBO/scene-graph related. The next step should be source/destination edge alignment in `paintWaterfall()` / FBO texture geometry, not a cosmetic overlay rectangle.

If the edge remains even with `paintTarget=image`, the next candidate to isolate is the outer `analyzerBackdrop` border rather than the renderer.
