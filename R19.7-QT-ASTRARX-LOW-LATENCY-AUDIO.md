# R19.7 Qt5 AstraRX Low-Latency Audio Output

## Purpose

Connect the existing iScanMR10 Qt5 receiver client to the current AstraRX Qt5
compatibility WebSocket and drive decoded analog/digital speech to the local
ALSA output with bounded low latency.

This revision changes the Qt5 playback side only. It does **not** change
AstraRX RF/DSP/D-Star/CodecServer behavior, Qt frequency ownership, FFT
rendering, QML behavior, database behavior, or recorder behavior.

## Transport contract kept unchanged

Qt keeps using one AstraRX compatibility connection:

```text
ws://127.0.0.1:8074/ws/qt5
```

Override only when required:

```bash
export ASTRARX_WS_URL=ws://<astrarx-host>:8074/ws/qt5
```

The existing wire contract is preserved:

- binary type 2: analog/SD PCM16, 12 kHz
- binary type 4: HD/digital PCM16, 16 kHz
- Qt resamples either route statefully to one 48 kHz mono S16_LE ALSA owner

No second `/ws/audio` socket is added, so the established Qt5 receiver control,
frequency, FFT, squelch, and audio ownership stay on the same compatibility
session.

## Why the playback side was changed

Before R19.7 the local player accumulated approximately:

```text
software staging target : ~100 ms
ALSA requested buffer    : ~100 ms
ALSA period              : ~20 ms
```

and then added a wall-clock sleep after `snd_pcm_wait()`/`snd_pcm_writei()`.
ALSA is already the playback clock, so the extra sleep could allow decoded
speech to accumulate behind the live RF stream.

R19.7 defaults:

```text
ALSA buffer              : 40 ms
ALSA period              : 10 ms
software staging         : 20 ms
producer queue bound     : 8 chunks
ALSA start threshold     : ~2 periods
ALSA avail_min           : 1 period
manual post-write sleep  : removed
```

The values are runtime-tunable without rebuilding:

```bash
ISCAN_AUDIO_BUFFER_MS=40
ISCAN_AUDIO_PERIOD_MS=10
ISCAN_AUDIO_STAGE_MS=20
ISCAN_AUDIO_MAX_QUEUE_CHUNKS=8
```

Keep the defaults for the first hardware test. Lower values should only be
tried after proving zero/near-zero underruns on the actual codec/I2S output.

## Runtime architecture

```text
AstraRX
  |
  | /ws/qt5
  | type 4 @ 16 kHz for D-Star/DMR/YSF/NXDN
  v
WebSocketClient
  |
  | PCM16 + software volume
  v
stateful Speex SRC
  |
  | 48 kHz mono S16_LE
  v
AlsaAudioPlayer
  |
  | 20 ms staging / 10 ms period / 40 ms device buffer
  v
ALSA default PCM
  |
  v
codec / I2S / speaker
```

## Build

Use qmake as required by this project.

Jetson Orin:

```bash
cd ~/iScanMR10-R19.7-astrarx-low-latency-audio-src
make clean 2>/dev/null || true
qmake iScanMR10.pro -spec linux-jetson-orin-g++
make -j"$(nproc)"
```

Desktop development build:

```bash
qmake iScanMR10.pro -spec linux-g++
make -j"$(nproc)"
```

## AstraRX prerequisite

Before starting Qt:

```bash
systemctl is-active astrarx.service
ss -ltnp | grep ':8074'
curl -fsS http://127.0.0.1:8074/api/status >/dev/null
```

All three should pass.

## Run

For AstraRX on the same Orin:

```bash
export ASTRARX_WS_URL=ws://127.0.0.1:8074/ws/qt5
./iScanMR10
```

For the first test do not override the R19.7 audio defaults.

## Expected logs

Connection/audio ownership:

```text
[ASTRARX-BACKEND] WebSocket = ws://127.0.0.1:8074/ws/qt5
[R19.7 ASTRARX AUDIO] revision=20260828-r19.7-low-latency-alsa-output
[R19.7 AUDIO LOWLAT CONFIG] ... buffer_ms=40 period_ms=10 stage_ms=20 ...
[R19.5 AUDIO OWNER] single ALSA output ... output_rate=48000
[R19.4 ALSA RATE] requested=48000 actual=48000 ...
[R19.7 AUDIO LOWLAT] avail_min_frames=... start_threshold_frames=...
```

During D-Star speech:

```text
[R19.5 QT AUDIO] route=HD/type4 post_volume_peak=... hd_rx_frames=...
[R19.7 QT AUDIO LATENCY] alsa_delay_ms=... staged_ms=... queue_chunks=...
```

A healthy D-Star output path should show:

- `hd_rx_frames` increasing
- `push_frames` increasing
- `alsa_written_frames` increasing
- non-zero `post_volume_peak` while speech is present
- `queue_chunks` normally small
- no continuous queue drops
- no continuously increasing underrun/recover count

## A/B tuning only after default validation

If the default 40/10/20 ms profile is stable, a lower-latency experiment can
be done without rebuilding:

```bash
export ISCAN_AUDIO_BUFFER_MS=30
export ISCAN_AUDIO_PERIOD_MS=10
export ISCAN_AUDIO_STAGE_MS=10
export ISCAN_AUDIO_MAX_QUEUE_CHUNKS=6
./iScanMR10
```

Return to the defaults immediately if speech becomes intermittent or underruns
increase.

## Rollback

The only functional source changes are in:

- `alsaaudioplayer.cpp`
- `alsaaudioplayer.h`
- one R19.7 startup marker in `Mainwindows.cpp`

Restoring those files from the previous source returns the R19.5 playback
buffering behavior. The AstraRX protocol is unchanged.
