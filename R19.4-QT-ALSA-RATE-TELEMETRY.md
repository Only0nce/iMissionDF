# R19.4 Qt ALSA Actual-Rate Telemetry

Baseline: iScanMR10 R19.2.1 (includes R18 native FFT renderer, R19.0 Digital mode contract, R19.2 DMR session control, and R19.2.1 QML startup fix).

Only `alsaaudioplayer.h/.cpp` are changed.

After ALSA hardware parameters are committed, the player calls `snd_pcm_hw_params_current()` and `snd_pcm_hw_params_get_rate()` to obtain the active rate. It records the value atomically and emits:

`[R19.4 ALSA RATE] requested=<Hz> actual=<Hz> error_ppm=<ppm> buffer_frames=<N> period_frames=<N> format=<...>`

If absolute rate error exceeds 100 ppm it emits:

`[R19.4 ALSA RATE MISMATCH] ...`

Audio-thread pacing uses the active ALSA frame rate. The incoming Digital audio contract itself is not resampled or altered in Qt; AstraRX remains responsible for delivering the 16 kHz Qt compatibility stream.
