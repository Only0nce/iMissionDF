# R20.4-SPECTRUM-CUDA1.15-SELECTED-FREQUENCY-METRICS

## Scope

Derived surgically from R20.4-SPECTRUM-CUDA1.14. Runtime changes are limited to:

- `FftDisplayItem.h`
- `FftDisplayItem.cpp`
- `SpectrumGLPlot.qml`

CUDA kernels/workers, Waterfall history, FPS60 presentation, Floating Workspace, Audio, Network/5G, WebSocket protocol, and frequency ownership are unchanged.

## Problem

The sticky Peak/Noise/SNR HUD was physically attached to the selected receiver band, but its values still came from viewport-wide measurements:

- Peak = strongest FFT bin in the visible viewport.
- Noise = 30th-percentile sample over the visible viewport.
- SNR = viewport peak minus viewport noise.

This meant an unrelated stronger signal elsewhere on screen could be displayed in the HUD attached to the frequency the operator was listening to.

## New measurement contract

The sticky HUD now reports receiver-local values:

- `LEVEL`: FFT level at the exact selected/listening frequency (`centerFreq + offsetFrequency`).
- `NOISE`: local noise floor around that selected channel, excluding the receiver bandwidth as a guard region.
- `SNR`: selected LEVEL minus local NOISE.
- Frequency readout: selected/listening frequency, not the frequency of the strongest viewport peak.

The existing viewport-wide `peakDb`, `noiseFloorDb`, `snrDb`, and `peakFrequencyHz` API remains unchanged. Waterfall P/N markers continue to use those legacy viewport-wide metrics, preventing an unrelated UI regression.

## Exact-frequency level

The selected frequency is mapped to a fractional FFT index across the full acquisition axis. The two neighboring dB bins are linearly interpolated. This avoids whole-bin jumps when the selected receiver frequency lies between FFT bins.

No temporal averaging is applied to LEVEL. Values refresh at the existing native measurement cadence (nominally 5 Hz), and a tune/reference change triggers an immediate recomputation using the latest FFT frame.

## Local noise floor

Noise is estimated around the selected channel, not over the complete viewport.

1. Compute FFT bin width from `sampleRate / (N - 1)`.
2. Exclude a guard region at least half the active demod bandwidth and at least two FFT bins.
3. Build a local outer window that scales with the receiver bandwidth, with a minimum number of surrounding bins.
4. Sample at most roughly 256 bins to keep CPU cost bounded.
5. Use the 30th percentile of the local samples as the noise-floor estimate.

This keeps wanted-signal energy out of the noise estimator while remaining robust to nearby carriers.

## QML data path

```text
centerFreq + offsetFrequency
          |
          v
measurementFrequencyHz
          |
          v
FftDisplayItem native C++
    |        |        |
  LEVEL   LOCAL N    SNR
    \        |       /
     +-------+------+
             |
             v
       Sticky HUD only
```

Large FFT buffers remain native C++ data and are never copied into QML/JavaScript.

## UX

The card keeps all CUDA1.14 behavior:

- sticks to the selected receiver band;
- automatically flips left/right near plot edges;
- tapping anywhere on the card toggles LOCK opacity;
- LOCK does not freeze measurements or tuning.

The first label changes from `PEAK` to `LEVEL` because the value now represents the selected frequency rather than the maximum of a span.


## Target validation

Recommended real-RF check:

1. Tune the selection bar to a weak/quiet frequency A.
2. Ensure a much stronger carrier B is visible elsewhere in the same Spectrum viewport.
3. Move/tune A slightly while leaving B unchanged.
4. Sticky `LEVEL` must follow A, not B.
5. Move the selection bar onto B; LEVEL/SNR should then rise to B.
6. Change demod bandwidth and confirm local NOISE changes only as expected from the new guard/window region.
7. Verify Waterfall P marker still follows the strongest visible peak, preserving existing legend semantics.
