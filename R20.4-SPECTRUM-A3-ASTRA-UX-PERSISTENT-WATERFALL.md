# R20.4-SPECTRUM-A3 — AstraRX WebV2-inspired Spectrum/Waterfall UX

## Scope lock

This revision derives surgically from R20.4 and changes only the Spectrum/Waterfall subsystem:

- `SpectrumGLPlot.qml`
- `WaterfallScaleControl.qml`
- `FftDisplayItem.cpp`
- `FftDisplayItem.h`

Explicitly unchanged: Audio/ALSA, Network/WiFi/5G, Recorder, Database, AstraRX reconnect, frequency ownership, DSP mode, receiver protocol, Memory/Log widgets and global application navigation.

## Reference

AstraRX WebV2 AB6/AB7/AB8 is used as the presentation and interaction reference, not copied wholesale. The iScanMR10 page keeps its existing overall footprint and lower Memory/Log area.

## A1 — Analyzer visual hierarchy

- Existing top-half analyzer footprint is preserved.
- Internal ratio becomes approximately 58% Spectrum / 42% Waterfall.
- Local analyzer colors use the Astra dark/teal instrument language.
- Live trace changes from bright green to teal `#35D5BD`.
- Max Hold uses amber `#FFC55A`.
- A low-opacity fill is drawn under the live spectrum trace.
- Compact native-data HUD shows Peak, Noise Floor and SNR.
- HUD values are scalar QML properties only and update at ~5 Hz.

## A2 — Data-driven waterfall intensity scale

- UI level semantics are `dBFS`; no calibrated dBm claim is made.
- Waterfall legend uses the same palette stop list as the native renderer.
- Native C++ interpolates between palette stops for smooth color transitions.
- `P` indicates the current visible-spectrum peak.
- `N` indicates the current visible-spectrum noise estimate.
- Peak/noise/SNR are computed in C++ from the current visible RF window.
- Manual horizontal intensity control remains available and is restyled locally.
- Retained dB history is recolored when the display min/max or palette changes, so the legend remains consistent with historical pixels.

## A3 — True persistent waterfall

Old R20.4 path:

```
full-axis FFT row
   -> crop to current zoom/pan
   -> color
   -> store visible image row
```

This made historical rows use different RF mappings after view changes and `applyZoom()` explicitly cleared history.

New path:

```
full-axis waterfall display row
   -> bounded full-axis dB history
   -> same-axis color history
   -> crop only during paint()
   -> visible Waterfall
```

History is NOT cleared by:

- Zoom
- Pan
- viewport navigation
- visible item resize
- page runtime gate / temporary page inactivity

History IS cleared by:

- explicit Waterfall `Clear`
- incompatible acquisition-axis change (`fullStartFreq` or sample rate)
- incoming full-axis row width change

The history backing store is bounded:

- max RF bins: 4096
- rows: 1024
- typical 1280-bin color history: ~5 MiB
- typical 1280-bin dB history: ~5 MiB

No unbounded row list is used.

## Pause/Clear semantics

- `Pause` stops new waterfall row acquisition only.
- Existing history is retained.
- `Resume` continues from retained history.
- `Clear` explicitly discards history.
- Spectrum and receiver/audio processing continue while waterfall is paused.

## Stability invariants retained from R20.4

- `QV4_FORCE_INTERPRETER=1` remains owned by R20.3/main startup.
- FFT-sized JavaScript arrays are not reintroduced.
- Spectrum/Waterfall data arrives as native `QVector<float>`.
- Max Hold/Peak Scan backend behavior is unchanged.
- No new `mainWindows.sendmessage()` command path is added.
- No receiver center/offset ownership logic is changed.

## Target validation

1. Compare frequency axis and peak placement against R20.4.
2. Zoom/pan repeatedly while waterfall is active; old rows must stay aligned to RF.
3. Resize/change page and return; retained history must not be relabelled.
4. Change intensity range; all retained waterfall rows should follow the same legend mapping.
5. Pause 10–30 seconds; history must remain. Resume must continue without clearing.
6. Change RF center/source span; history must clear because the acquisition axis changed.
7. Verify Peak / Noise / SNR values remain finite and plausible.
8. Soak with Spectrum/Waterfall active while monitoring the existing R20.4 stability diagnostics.
