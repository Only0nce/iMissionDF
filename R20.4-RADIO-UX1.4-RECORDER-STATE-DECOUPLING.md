# R20.4 RADIO UX1.4 — Recorder State / Mute-SQL Decoupling

Base: R20.4 RADIO UX1.3 Volume/Speaker Adjustment Clears Mute + NET-ENDPOINTS1.3 legacy TopNetworkDrawer restore.

## Problem
The Main-page REC indicator was driven by `sqlActiveChanged(bool)` rather than the actual recorder state. At the same time, the mute/unmute transaction and Volume/Speaker adjustments could write SQL/squelch state. This coupled three independent concerns:

- playback mute / volume,
- RF SQL/squelch,
- recorder state.

The result was that unmuting or adjusting volume while muted could change SQL and therefore affect recorder gating, while the REC icon could stop blinking merely because SQL changed even if the external recorder state had not yet been confirmed.

## Design
Use three independent state paths:

1. **Playback audio** — `WebSocketClient::setSpeakerVolumeMute()` and volume APIs.
2. **RF SQL** — existing SQL controls and `Mainwindows::onSQLChanged()`.
3. **Recorder status** — `LogWatcher` -> `Mainwindows::m_lastRecState` -> `onRecStatusChanged(bool)` -> Main-page REC indicator.

Mute/Volume/Speaker must never mutate SQL. The REC indicator must never use SQL as its state source.

## Product changes

### HomeDisplay.qml
- `unmuteFromUserVolumeAdjustment()` now clears playback mute only.
- Removed SQL/squelch writes from software Volume changes.
- Removed SQL/squelch replay from Speaker volume changes.
- Removed SQL/squelch replay from Headphone volume changes as part of the same separation of concerns.
- Explicit SQL control path remains unchanged.

### MyDrawer.qml
- `toggleVolumeMute()` now calls only `wsClient.setSpeakerVolumeMute(nextMute)`.
- No `setSqlLevel()`, DSP squelch message, or `setSqlOffManual()` is issued by mute/unmute.

### Mainwindows.cpp / Mainwindows.h
Added QML state replay APIs:

```cpp
Q_INVOKABLE bool getRecActive() const;
Q_INVOKABLE QString getRecorderState() const;
```

They replay `m_lastRecIsRecord` and `m_lastRecState`, which are fed by `LogWatcher` on `/tmp/alsarecd_id_1.log`.

Added diagnostics:

```text
[REC-STATE] state= RECORD active= true
[SQL-STATE] active= true/false
```

### RadioScanner.qml
REC icon now:
- initializes from `mainWindows.getRecActive()`,
- follows `mainWindows.onRecStatusChanged(bool)`,
- blinks only while the recorder backend reports RECORD.

It no longer reads `getSqlActive()` or listens to `sqlActiveChanged()`.

### websocketclient.cpp
Added state-change diagnostic:

```text
[AUDIO-MUTE] muted= true/false
```

No functional audio backend behavior was changed.

## Expected runtime behavior

### Mute while recorder is RECORD
```text
[AUDIO-MUTE] muted= true
```
SQL must not change because of the mute action. If recorder remains RECORD, REC continues blinking.

### Adjust Volume/Speaker while muted
```text
[AUDIO-MUTE-UX] user volume adjustment -> unmute playback only
[AUDIO-MUTE] muted= false
```
No SQL write is generated by that gesture. If recorder remains RECORD, REC continues blinking.

### Real RF SQL transition
A real SQL transition still follows the existing recorder policy. If alsarecd changes state, LogWatcher reports it and the REC icon follows the recorder state, not a guessed UI state.

## Target validation
1. Start with SQL open and wait until log shows `[REC-STATE] state= RECORD active= true`.
2. Confirm REC icon blinks.
3. Press Mute. Confirm `[AUDIO-MUTE] muted= true`; no new `[SQL-STATE] active= false` should be caused by that press; REC should keep blinking while recorder remains RECORD.
4. While muted, move Volume or Speaker. Confirm playback unmutes; no SQL transition should be caused by the gesture; REC should keep blinking while `[REC-STATE]` remains RECORD.
5. Change RF/SQL condition genuinely. Confirm `[SQL-STATE]` changes according to RF state and `[REC-STATE]` follows the external recorder policy. The REC icon should follow `[REC-STATE]`.
6. Reopen/return to the Main page while recorder is already RECORD. `getRecActive()` should replay the current state and REC should blink immediately.

## Scope preserved
No changes were made to Network Settings, Endpoints, VPN, TopNetworkDrawer, RFSoC TCP, database schema, recorder socket protocol, or alsarecd state machine.
