# R19.2.1 QML Startup Fix

## Root cause
`main.qml` used `synchronized` as a JavaScript/QML function parameter in the
`Connections.onDigitalVoiceStateChanged` handler. The target Qt 5 QML parser
rejects that reserved identifier, producing `Expected token ')'` at the first
character of `synchronized`.

## Primary fix
Rename only the local QML handler parameter from `synchronized` to `syncOk`.
The signal argument order is unchanged; AstraRX/Qt digital-voice protocol is
unchanged.

## Failure-path hardening
On QML load failure, explicitly destroy `QQmlApplicationEngine` before returning
from `main()`. This preserves the same lifetime ordering used by the normal
shutdown path: QML objects are destroyed while all C++ context backends are
still alive.

This is intended to prevent secondary cleanup faults such as the observed
`free(): double free detected in tcache 2` after `rootObjects empty`.
