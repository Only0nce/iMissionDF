# R20.4-SPECTRUM-CUDA1.16-ASTRARX-SMETER-METRICS

## Purpose

This revision is derived surgically from `R20.4-SPECTRUM-CUDA1.15-SELECTED-FREQUENCY-METRICS`.
It corrects the sticky receiver metrics card after source inspection showed that the project already receives AstraRX `type="smeter"` data for the tuned receiver.

## Root cause

CUDA1.15 generated `LEVEL` from a single/interpolated wideband FFT position. That value is useful as an FFT diagnostic, but it is not the same measurement as the receiver S-meter already produced by AstraRX. The existing project path is:

`AstraRX smeter -> WebSocketClient::smeterValueUpdated() -> Mainwindows/QML S-meter`

The two measurement domains must not be treated as interchangeable.

## Runtime changes

Only these runtime files are changed:

- `FftDisplayItem.h`
- `FftDisplayItem.cpp`
- `SpectrumGLPlot.qml`

No CUDA kernel/plugin, Waterfall worker/history, audio, network, scan/memory, or frequency-control implementation is changed.

## Measurement contract

### LEVEL

The sticky HUD now uses the existing AstraRX S-meter sample received through `WebSocketClient::smeterValueUpdated(double)`.

`FftDisplayItem` subscribes to that existing signal with a queued scalar connection and exposes:

- `receiverLevelValid`
- `receiverLevelDb`
- `receiverLevelFrequencyHz`

When the selected receiver frequency changes, the old S-meter value is invalidated immediately. A 120 ms settle guard rejects an immediately arriving sample that can still belong to the previous DSP offset while the QML 20 ms offset-command coalescer/backend applies the new tuning.

The QML HUD preserves the project's current `dBm` presentation convention so its LEVEL is directly comparable to the existing Analog S-meter. Absolute dBm calibration is still a receiver/system calibration concern; this revision does not invent a new calibration.

### NOISE

`NOISE` remains a local FFT-domain estimate in dBFS. It is not derived from, nor subtracted from, AstraRX S-meter data.

CUDA1.16 improves the exclusion guard by passing the actual `low_cut` and `high_cut` into `FftDisplayItem`. This matters for asymmetric demodulator modes such as SSB. The current wanted passband plus two FFT-bin guard bins is excluded, and a bounded nearby region is sampled. The existing 30th-percentile estimator is retained.

### SNR

`SNR` remains entirely in the FFT domain:

`FFT level at selected frequency - local FFT noise floor`

It therefore remains dimensionally valid and is **not** calculated as `AstraRX S-meter - FFT noise`.

## Diagnostic telemetry

Every ~5 seconds, the Spectrum item prints a low-rate comparison record:

```text
[RF-METRICS] freq=95.5MHz astra_smeter=-82.3 fft_point=-89.7 fft_local_noise=-121.1 fft_snr=31.4 diagnostic_delta=7.4 bw=15000 low_cut=-7500 high_cut=7500
```

`diagnostic_delta` is observation only. It is deliberately never fed back as a calibration correction because receiver S-meter and FFT-bin dBFS have different bandwidth/reference semantics.

## Target validation

Static/source validation can be performed off-target. Final runtime acceptance must be done on the Jetson Orin Qt 5.15.2 target.

Expected startup marker:

```text
[R20.4-SPECTRUM-CUDA1.16-ASTRARX-SMETER-METRICS] levelSource=astrarx-smeter fftNoise=local fftSnr=local cutAwareNoise=1
```

Recommended field test:

1. Tune to a stable carrier.
2. Compare sticky `LEVEL` with the existing bottom S-meter; after the S-meter refresh/settle interval they should follow the same AstraRX value.
3. Move the receiver to a different channel. LEVEL should blank briefly rather than showing the old channel's value, then update from a new AstraRX S-meter sample.
4. Change analog bandwidth or an asymmetric mode and verify local `NOISE`/`SNR` continue updating without using the signal passband as noise.
5. Capture `[RF-METRICS]` lines for several strong/weak signals and bandwidths before deciding whether any further noise/SNR calibration is justified.
