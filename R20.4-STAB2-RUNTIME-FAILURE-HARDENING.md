# R20.4-STAB2 — Runtime Failure / Termination Hardening

Base: latest integrated source containing NET-AUTH3 direct Viewer entry, NET-ENDPOINTS1.3 legacy top drawer fallback, and RADIO UX1.4 recorder-state decoupling.

## Scope

This revision addresses errors/warnings observed in the 2026-09-16 runtime log and hardens adjacent lifetime/failure paths that could terminate the full UI process. The design rule is:

> A peripheral, optional service, remote endpoint, or secondary UI surface may degrade, but it must not terminate the main application unless the root QML/application state is fundamentally unusable.

## Observed issues addressed

### QML / StackView / Canvas
- `QML Canvas: Unable to use getContext() at this time`
- `clearRect of null`
- `StackView has detected conflicting anchors`
- `StorageUsed.qml: root is not defined`
- invalid `Connections.onValuePctChanged`

Changes:
- QMLMap root no longer anchors itself to a StackView parent.
- ViewerPage root no longer anchors itself to a StackView parent.
- QMLMap Canvas clear is deferred to `onPaint`; every touched Canvas context is null-guarded.
- StorageUsed uses its own direct property-change handler and a null-guarded Canvas context.

### SQL / SHD_AMP GPIO warning flood
The SHD_AMP line is requested as an output. The legacy `newGPIOClass::getValue()` rejected every output line, so each SQL transition could report a false read failure.

Changes:
- successful output writes are cached in `newGPIOClass`;
- output-state reads return the last successfully driven state;
- true GPIO read/write faults are logged once until recovery;
- SQL state remains valid even if one GPIO is unavailable;
- null/failing GPIO objects no longer create an unchecked dereference path.

### RFSoC TCP unreachable / reconnect storm
Changes:
- reconnect timer is single-shot;
- bounded exponential retry: configured base (normally 10 s) → 20 s → 40 s → 60 s cap;
- duplicate reconnect scheduling is suppressed;
- successful connection resets the retry delay;
- explicit disconnect and destructor stop reconnect/heartbeat timers and abort the socket safely.

### Database idempotent UPDATE warning
MySQL may report zero affected rows when the requested value already equals the stored value.

Change:
- zero-row UPDATE is checked against `Parameter.id=1` and logged as unchanged rather than as a false failure; a truly missing row remains a warning.

### WebSocket lifetime safety
Changes:
- recorder target wrappers in the main ChatServer use `QPointer<QWebSocket>`;
- queued sends re-check the guarded pointer and connected state;
- disconnected sockets are removed from all auxiliary lists before deletion;
- optional recorder IDs no longer flood warnings;
- ChatServerWebRec now removes disconnected sockets from its web-client list and checks connected state before sends;
- teardown detaches client containers before closing sockets, preventing re-entrant list mutation;
- QML-originated recorder commands no longer propagate an uninitialized `QWebSocket*` into DB response paths.

### MAX31760 / I2C Remote I/O failure
The legacy fan-control path used `system("i2ctransfer ...")`; a missing/NACKing I2C device produced `Remote I/O error`, while missing thermal sysfs files called `exit(EXIT_FAILURE)` from the fan worker.

Changes:
- fan profiles are sent using bounded in-process `/dev/i2c-0` transactions;
- the exact 93-byte profile format is retained, including separate control/profile bytes for startup, safe and normal modes;
- I2C failure uses bounded exponential retry and one-shot fault logging;
- thermal telemetry failure keeps the previous fan profile and retries instead of exiting;
- fan temperature/profile evaluation is one cycle per worker iteration rather than nested infinite loops.

### Recorder pthread shutdown
The recorder subsystem starts multiple pthread workers. All started workers now share an atomic stop flag and are joined before QObject children/database state are destroyed. The hourly cleanup worker is also reaped before `pthread_t` reuse and before shutdown.

### Unix recorder-status socket
- socket/bind failure is degraded recorder-status integration, not `qFatal()`;
- only one `/tmp/recd_status.sock` listener is created by mainwindowsiRec;
- descriptor/notifier/path ownership is cleaned up on destruction.

### SPI / input peripheral failure
- SPI initialization failure no longer calls `exit(-1)`; the SPI path becomes unavailable/degraded and transactions return failure.
- missing input-event device no longer calls `exit(EXIT_FAILURE)` from its worker.

## Model size warning
A defensive non-negative clamp is applied to the numeric Repeater models in the temporarily restored TopNetworkDrawer. The runtime log does not identify a QML URL for `Model size of -16/-17`, so this revision does **not** claim that warning is fully root-caused. `[NAV]` diagnostics remain in MainPage to correlate any recurrence with the active page during target testing.

## Intentional process exits retained
Firmware-update completion and fatal root-QML initialization paths are intentionally not converted into degraded behavior. Those are explicit application lifecycle decisions, not peripheral failure paths.

## Target validation
1. Boot with the fan controller unavailable/NACKing: UI must remain alive; one MAX31760 warning is expected, not repeated shell `Remote I/O error` spam.
2. Boot with RFSoC target unreachable: retry intervals must back off and UI/navigation remain responsive.
3. Exercise SQL repeatedly: no continuous `Failed to read SHD_AMP state`; real GPIO failure should log once and recover without crash.
4. Navigate DOA ↔ Map ↔ Recorder ↔ Network repeatedly: no Canvas-null exceptions or StackView anchor warnings from ViewerPage/QMLMap.
5. Open recorder Storage page: no undefined `root` / invalid Connections warning.
6. Reconnect/disconnect recorder/web clients repeatedly and then terminate the app: no use-after-free, `QProcess destroyed`, or pthread lifetime crash.
7. Watch for `Model size of -16/-17`; if it remains, capture the adjacent `[NAV]` line and active page for the next surgical pass.
