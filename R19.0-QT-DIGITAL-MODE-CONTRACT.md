# R19.0 Qt Digital Mode Contract Fix

## Scope

Preserves the R18.1 native FFT renderer and fixes the Qt -> AstraRX digital demod/audio control contract.

## Fixes

- Digital selector uses `receiverIndex` (global receiverMode index), not ListView-local `index`.
  - DATA=7, DMR=8, D-Star=9, NXDN=10.
- Resets bandwidth row to 0 whenever receive mode changes.
- D-Star/NXDN UI bandwidth aligned to 6.25 kHz (`-3125..+3125`).
- Adds `[R19 DEMOD APPLY]` and `[R19 DEMOD TX]` diagnostics.
- Warns when Qt sends a mode not supported by the AstraRX native Qt5 parser (`usbd`, `cw`, `sam`, etc.).
- Adds transition-safe SD/HD audio ownership:
  - analog native modes -> type 2 / 12 kHz
  - DMR/YSF/D-Star/NXDN -> type 4 / 16 kHz
  - unknown/legacy -> permissive ANY
- Flushes both queued and ALSA-staged old audio on mode transitions without cross-thread ALSA access.
- Drops stale packets from the previous route after ownership switches.

## Expected validation

Selecting DMR must produce:

```text
[R19 DEMOD APPLY] receiverIndex=8 mode=dmr low=-6250 high=6250 dmrFilter=3
[R19 DEMOD TX] mode= dmr low= -6250 high= 6250 dmrFilter= 3
[R19 AUDIO ROUTE] mode= dmr expected= HD/type4 ... queues=flushed
```

D-Star must use index 9 and `-3125..+3125`; NXDN index 10 and the same bandwidth.
