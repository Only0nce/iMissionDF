# R19.5 Digital Audio End-to-End Proof / Single ALSA Owner

Baseline: iScanMR10 R19.4 (`src.tar(7).xz`).

## Architecture

Before:

- SD/analog: independent 12 kHz `AlsaAudioPlayer` -> `snd_pcm_open("default")`
- HD/digital: independent 16 kHz `AlsaAudioPlayer` -> `snd_pcm_open("default")`
- both QThreads started on every AstraRX connection

This allowed an ALSA ownership race on systems where `default` is not a multi-open PCM.

R19.5:

- exactly one `AlsaAudioPlayer`
- ALSA requested output rate: 48 kHz, mono S16_LE
- SD/type2 PCM: stateful Speex SRC 12 kHz -> 48 kHz
- HD/type4 PCM: stateful Speex SRC 16 kHz -> 48 kHz
- route changes flush the one queue and reset both SRC histories
- ALSA initialization retries every 1 second while the player is running

The AstraRX WebSocket protocol is unchanged: `connectionproperties` still advertises 12 kHz SD and 16 kHz HD. Conversion to the single hardware clock is local to Qt.

## End-to-end diagnostics

`[R19.5 AUDIO ARCH]` proves the new single-owner code is present.

`[R19.5 ALSA OWNER]` proves ALSA opened and reports requested/actual rate.

`[R19.5 ALSA RETRY]` means Linux/another process currently owns or rejects the PCM; retry is automatic.

`[R19.5 QT AUDIO]` reports:

- route (SD/type2 or HD/type4)
- post-volume PCM peak
- received frame/byte counters
- successful enqueue counters
- SRC input/output frames
- actual ALSA written frames
- underrun/recovery counters

AstraRX R19.5 adds `[R19.5 QT5 AUDIO TX]` after `qt5_audio_adapter_.process()` produces a packet, including wire type, packet rate, sample count, total frames/bytes and gate state.

## Expected digital proof chain

For DMR/D-Star/NXDN voice:

1. AstraRX `[DIGITAL CLOCK VERIFY] ... pcm48_sps ...`
2. AstraRX `[R19.5 QT5 AUDIO TX] ... wire_type=4 packet_rate=16000 gate=1`
3. Qt `[R19.5 QT AUDIO] route=HD/type4 post_volume_peak=>0 ...`
4. Qt `alsa_out_frames` increases
5. Qt `alsa_written_frames` increases
6. `[R19.4 ALSA RATE] requested=48000 actual=48000` (or an explicit mismatch warning)

If step N succeeds and step N+1 does not, the fault boundary is directly localized.
