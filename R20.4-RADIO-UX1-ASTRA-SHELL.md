# R20.4-RADIO-UX1-ASTRA-SHELL

## Goal

First production pilot of the Astra-inspired UX/UI direction on the **real iScanMR10 Radio page**, derived from the user-provided `POP.tar(1).xz` baseline.

Baseline SHA-256:

`5a8f3d0f9e94e4363daefd70e4614b523ce7560385a23c1c9c49c9b2a71fc2f3`

This revision deliberately does **not** replace the Radio architecture. It restyles the existing controls while preserving their IDs, signals, drawers, receiver state ownership, preset flow, recorder indication, AstraRX integration, and the CUDA1.26 Spectrum/Waterfall path.

## Runtime files changed

- `RadioScanner.qml`
- `SpectrumGLPlot.qml`

No C++ backend, CUDA kernel/worker/plugin, WebSocket, recorder, network, database, or receiver configuration code is changed.

## Radio header redesign

The original solid teal blocks are replaced with a dark RF-instrument shell:

- header background: `#08131D`
- control surface: `#0D1D28`
- hover: `#132D3D`
- pressed: `#173C50`
- selected/rotary state: `#123848`
- border: `#294655`
- Ice/Cyan accent: `#45C9E8`
- primary text: `#EAF6FC`

### Existing functions preserved

The following real project controls remain wired to the same logic:

- editable frequency + frequency unit/rotary selection
- RF Scan drawer
- Analog/Digital receiver-mode drawer
- modulation selector
- bandwidth selector
- SQL drawer
- software volume
- headphone/phone level
- speaker level
- New/Save preset flow
- REC state driven by SQL activity
- CPU temperature telemetry

Preset creation still uses the existing `configManager.addOrModifyPreset()` and `/var/lib/openwebrx/preset.json` persistence path.

## Frequency card

The large receiver frequency remains the authoritative existing `freqScan`/`SpectrumGLPlot` flow. Only presentation changes:

- explicit `FREQUENCY` caption
- dark bordered instrument card
- large monospace readout
- Ice Blue unit control
- existing out-of-range red validation retained

## Spectrum / Waterfall divider

The previous 3-second HOLD button behavior is removed.

New behavior:

- symbol is visually integrated into the Spectrum/Waterfall split line
- no pill/button background
- no HOLD state
- direct vertical drag
- visible symbol approximately `30 x 20 px`
- invisible hit target `180 x 44 px` for touch usability
- existing split limits remain `25% .. 72%`
- existing 16 ms resize coalescing remains

The symbol uses opposing chevrons plus three center dots to communicate vertical resize without looking like a normal push button.

## Preserved analyzer behavior

This revision intentionally preserves:

- CUDA1.26 shared/lockstep Spectrum + Waterfall presentation architecture

- persistent Waterfall history

- RF/S-meter calibration behavior
- Green live Spectrum / Red Max Hold
- sticky selected-frequency metrics

- Scan / Memory floating workspace

```bash

```
